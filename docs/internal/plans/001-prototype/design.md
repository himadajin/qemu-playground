# RISC-V Web Playground Design

## Purpose

ブラウザから RISC-V 向けの C またはアセンブリを入力し、ボタンを押すだけでコンパイルと QEMU 実行を行い、stdout、stderr、終了コード、コンパイル結果、必要に応じて生成アセンブリを確認できる Web playground を作る。

このツールは、プログラマが短いコード片を素早く試すための実行環境として設計する。
中心価値は「コードを貼る、必要ならオプションを指定する、実行結果を見る」ことにある。
比較、デバッグ、プロジェクト管理、ユーザー管理は目的に含めない。

## Context

対象言語は C とアセンブリに限定する。
C++ は扱わない。

対象アーキテクチャは RV64 Linux user-mode に固定する。
当初は RV32 も検討したが、RV32 Linux/glibc を再現性高く扱うには独自ツールチェーンビルドが重くなりやすいため、全体の単純さ、apt ベースの再現性、自己ホストしやすさを優先して RV64 に寄せる。

コンパイラは GCC に固定する。
複数コンパイラ比較や Clang 対応は目的外とする。
C は `riscv64-linux-gnu-gcc` で Linux ユーザープログラムとしてビルドし、実行は `qemu-riscv64` で行う。
アセンブリ入力も同じ RV64 Linux user-mode の単一実行ファイルへビルドして実行する。

1 回の実行で扱う入力は 1 コンパイル単位だけとする。
ブラウザ側で複数ファイルを保存・切替できても、それらは互いにリンクされるプロジェクトではなく、独立したスニペットとして扱う。

C をコンパイルした場合は、実行結果に加えて readonly な生成アセンブリを返す。
生成アセンブリは、C が RISC-V アセンブリへどのように変換されたかを確認するための補助表示であり、コンパイラが `-S` 相当で出力したものをそのまま見せる。

リポジトリはモノレポとし、Web フロントエンドとシミュレーター実行環境(API サーバー + runner)を単一リポジトリで管理する。
パッケージ管理は pnpm workspace を使う。

フロントエンドは Cloudflare 上の静的サイトとして配信し、実行環境は Docker Compose による自己ホストとして Cloudflare Tunnel 経由でのみ公開する。
フロントエンドと API は同一オリジンで、全体を Cloudflare Access で保護し、利用者を許可した少人数に限定する。
アプリケーション自体はユーザー管理・認証機能を持たない。
配信・運用・CI/CD の詳細は `infrastructure.md` が扱う。

任意コードを実行するため、実行は短命 runner コンテナで隔離する。
利用者が少人数に限られる前提で、レート制限や強い公開サービス向け防衛策は初期設計に含めない。
実行隔離とツールチェーンの詳細は `execution.md` が扱う。

ユーザー管理、アカウント、サーバー側データ永続化、URL をキーにした保存データ呼び出しは扱わない。
保存はブラウザ内のローカル保存とし、共有 URL はコード、言語、コンパイルオプションを URL に埋め込むことで実現する。

技術スタックは設計時点で固定する。
フロントエンドは React `19.2.7`、Vite `8.0.16`、TypeScript `6.0.3` を使う。
API サーバーは Node.js `24.16.0` LTS、TypeScript `6.0.3`、Fastify `5.8.5`、Zod `4.4.3` を使う。
コードエディタは Monaco Editor `0.55.1` を第一候補とし、アイコンが必要な UI では lucide-react `1.17.0` を使う。

## Direction

モノレポは `apps/web`(React/Vite フロントエンド)、`apps/api`(Fastify API サーバー)、runner イメージ定義、API リクエスト/レスポンスの Zod スキーマを共有する `packages/shared` 程度の構成にする。
共有スキーマにより、フロントエンドと API の型と検証を単一定義から導出する。
ディレクトリの細部は実装時に単純な形を選んでよい。

アプリケーションは、React/Vite の単一画面フロントエンド、Fastify API サーバー、実行専用 runner イメージの構成にする。
フロントエンドは、コード入力、実行操作、結果表示が 1 画面で完結する playground として扱う。
詳細な画面配置や視覚設計は `ui.md` で定義する。

フロントエンドは同一オリジンの `/api` を相対パスで呼ぶ。
配信経路と開発時の proxy 構成は `infrastructure.md` に従う。

API は単発の同期 `/run` エンドポイントを中心にする。
ブラウザはコード、言語、コンパイルオプションを送信し、サーバーはコンパイル結果、実行結果、stdout、stderr、終了コード、タイムアウト有無、C 入力時の生成アセンブリをまとめて返す。
対話型実行、WebSocket、ジョブ履歴、ジョブポーリングは初期設計に含めない。
実行するプログラムの標準入力は常に空として扱う。
対話的な stdin 送信だけでなく、事前に固定の標準入力を与える機能も初期設計に含めない。

Run の結果は、コードの実行結果と、Run 自体を実行できなかったエラーの 2 層に分けて扱う。
コンパイルエラー、実行時エラー、タイムアウト、成功は、いずれも正常な API レスポンス(HTTP 200)の結果ステータスとして返す。
リクエスト不正、同時実行上限超過、runner 起動失敗などの内部エラーは HTTP エラーステータス(400、429、500 など)で返し、実行結果と混ぜない。

結果ステータスは `success`、`compile_error`、`runtime_error`、`timeout` の 4 値とする。
`success` はビルドが成功し、プログラムがシグナルで異常終了せずに終了した状態を指す。
終了コードが 0 以外でも正常終了であれば `success` とし、判断は終了コードの表示に委ねる。
`runtime_error` はシグナルによる異常終了(セグメンテーションフォルトなど)を指す。
`timeout` は時間制限超過を指し、コンパイル段階と実行段階のどちらで発生したかを結果から判別できるようにする。

レスポンスには、結果ステータスに加えて、コンパイルログ、stdout、stderr、終了コード(得られた場合)、各出力の切り捨て有無、C 入力時の生成アセンブリを含める。
フィールドの厳密な定義は `packages/shared` の Zod スキーマを単一の情報源とし、この文書では論理的な内容だけを決める。

API サーバー本体はコンパイルや QEMU 実行を直接行わず、Run ごとに短命 runner コンテナへ委譲する。
隔離・制限・ツールチェーン・コンパイルオプションの安全な取り扱いは `execution.md` に従う。

コンパイルオプションは optional な文字列入力として扱い、未指定でも実行できることを必須にする。

フロントエンドの保存機能は LocalStorage または IndexedDB によるローカル保存とする。
保存対象はスニペット名、言語、コード、コンパイルオプション程度に絞る。
サーバーには保存しない。

共有 URL は、コード、言語、コンパイルオプションを URL に埋め込む。
URL を開いた時点でフォームが復元され、ユーザーが Run を押すと実行される。
URL 展開だけで自動実行しない。
埋め込み表現は可逆であることだけを必須とし、圧縮などのエンコード方式は実装時に選ぶ。
コードが長く URL が実用的な長さの上限を超える場合、Share は暗黙に切り詰めた URL を作らず、共有できないことをエラーとして扱う。

サンプルコードは C とアセンブリの両方を用意する。
サンプルは、開いた状態のまま Run すると stdout に出力が確認できる短いコードとして用意する。
解説のためのコメントや、段階的に学ばせるサンプル集は用意しない。
初期表示は C の hello world 相当を置いてよい。

デバッグ機能、GDB、対話型ターミナル、常駐プロセス、標準入力の供給(対話送信・固定入力とも)、C++、Clang、複数コンパイラ比較、逆アセンブル表示、複数ファイルビルド、ユーザー管理、サーバー側永続化、レート制限は初期設計から外す。

## Completion Conditions

- ブラウザで単一画面の playground を開き、C またはアセンブリのコードを入力できる。
- C コードを未指定のコンパイルオプションで実行し、RV64 Linux user-mode 上の stdout、stderr、終了コードを確認できる。
- アセンブリコードを実行し、RV64 Linux user-mode 上の stdout、stderr、終了コードを確認できる。
- C コードを実行した結果として、readonly な生成アセンブリを確認できる。
- コンパイルオプションを任意で指定でき、未指定でも実行できる。
- コンパイルエラー、実行時エラー、タイムアウト、通常終了が UI 上で区別して表示される。
- 実行結果のエラーと、Run 自体を実行できなかったエラー(リクエスト不正、同時実行上限超過、内部エラー)が API 上で区別される。
- スニペットをブラウザ内に複数保存し、切り替えて再実行できる。
- コード、言語、コンパイルオプションを埋め込んだ共有 URL を作成でき、その URL を開くと入力状態が復元される。
- URL 長の上限を超えるコードの Share は、切り詰めた URL を作らずエラーとして通知される。
- サンプル C コードとサンプルアセンブリコードを選択して実行できる。
- サーバー側にユーザーコードやスニペットを永続保存しない。
