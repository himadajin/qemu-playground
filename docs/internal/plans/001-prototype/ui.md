# RISC-V Web Playground UI

## Purpose

プログラマがブラウザを開いてすぐに C またはアセンブリを入力し、Run を押して実行結果を読める、ミニマルで高速な開発ツール UI を作る。

画面はコード入力、実行操作、結果表示の 3 要素に集中させ、この 3 つだけで成立する playground にする。

## Context

主対象はデスクトップとタブレット幅のブラウザである。
モバイルは主戦場ではないが、共有 URL を開いてコードと結果を読む体験が破綻してはいけない。

デスクトップでは、コードと結果を同時に見られる 2 ペイン構成を基本にする。
狭い画面では、長いコードと結果の往復をしやすくするため、`Code / Result` の切替に畳む。

保存済みスニペットは常設のファイルツリーとして見せない。
ファイルツリーやサイドバーを置くと IDE 化しやすく、中心体験である「コードを書く、Run する、結果を見る」の面積を削るためである。

デザインはライトモード固定にする。
ダークモード切替は初期 UI に含めない。
Radix Themes と Radix Colors を、統一感、アクセシビリティ、保守性のための土台として使う。
ただし Radix を使うこと自体を目的にせず、コードエディタには Monaco Editor のような用途に合う専用コンポーネントを使う。

色は白、黒、Radix gray、強調色の Radix blue に限定する。
状態色は、エラーなど意味がある場合に限って追加する。
グラデーションは使わない。
単色の面と細い境界線で構成する。

Monaco Editor は重くなりやすいため、初期ロードと Run 中の応答表示は UI の要件として扱う。
具体的な表示は Direction で定める。

## Direction

デスクトップ幅では、画面上部に細いツールバーを置き、その下を左右 2 ペインに分ける。
左ペインはコードエディタ、右ペインは結果ペインにする。
左右ペインは画面高を活用し、ページ全体を長くスクロールさせる構造にはしない。

上部ツールバーに置く操作は、言語切替、コンパイルオプション入力、`Run`、`Open`、`Save`、`Share` に絞る。
設定パネル、常設サイドバー、ファイルツリー、デバッグ操作、ターミナル操作は置かない。
`Run` は最も強い主操作として扱い、`Share` は現在のコード、言語、コンパイルオプションを URL に埋め込む一級操作として扱う。

コンパイルオプションは optional な入力であり、常に見える入力欄としてツールバー上に置く。
未指定でも Run できることは、空欄のまま Run できる挙動と、入力欄の placeholder(`-O2` のような指定例)で伝える。
説明文やツールチップは追加しない。

保存 UI は `Open` と `Save` から必要時だけ開く小さなダイアログに留める。
保存済みスニペット一覧はダイアログ内で扱い、常設しない。
保存対象はスニペット名、言語、コード、コンパイルオプション程度に見せる。

結果ペインは `Output / Build / Assembly` のタブを持つ。
Run 後は必ず `Output` を前面に出す。
`Output` は stdout、stderr、終了コード、実行状態を読む場所にする。
`Build` はコンパイルログを読む場所にする。
`Assembly` は C 入力時に生成されたアセンブリを readonly で読む場所にし、アセンブリ入力時には無効化または空状態として扱う。

コンパイルエラー、実行時エラー、タイムアウトは、結果ペイン内のログとして表示する。
上部や結果ヘッダーには `success`、`compile error`、`runtime error`、`timeout`、`running`、`error` の短い status badge だけを出し、詳細はログそのものを読ませる。
`error` は同時実行上限超過、サーバー内部エラー、通信失敗など、Run 自体を完了できなかった場合に使い、理由は `Output` のログとして表示する。
非ゼロ終了コードで正常終了した Run は `success` として扱い、判断は終了コードの表示に委ねる。

Run を押したら、`Run` ボタンは実行中表示になり、二重送信を避けるため無効化する。
結果ペインは `Output` に切り替わり、前回結果は比較用に残さず、現在の Run の実行中状態に置き換える。
古い結果と現在のコードの結果が混ざって見える状態を避ける。

初期ロードでは、ツールバーと画面骨格を先に表示する。
エディタ領域は固定サイズの editor shell と軽い skeleton または loading 表示を出し、Monaco の遅延ロードでレイアウトが大きく揺れないようにする。
凝ったローディング演出は作らず、ちらつきと不自然な組み替わりを避ける最低限の表示にする。

初期表示のサンプルは C の hello world 相当を基本にする。
サンプル切替は C とアセンブリを選べればよい。
サンプルの内容要件は `design.md` に従う。

狭い画面では、メイン領域を `Code / Result` の二択タブに畳む。
`Code` はツールバーとエディタを中心にし、`Result` は `Output / Build / Assembly` タブを含む結果ペインを表示する。
共有 URL を開いたユーザーが長いコードと実行結果をすばやく行き来できることを重視する。

モバイルでは編集体験を作り込むことを目的にしない。
ただし、コードが読める、結果が読める、Run できる、共有 URL で復元された内容を確認できる、という基本体験は壊さない。
画面幅が変わっても主要操作の意味や結果の所在が変わりすぎないようにする。

Radix Themes の Button、Tabs、Dialog、Select、TextField などの基本コンポーネントを優先して使う。
独自コンポーネントは toolbar、editor shell、result pane、status badge など、この playground 固有の構造に限定する。
フォーカス状態、キーボード操作、ラベル付けは Radix のアクセシビリティ前提を崩さない。

情報密度は開発ツールとして高めに設計する。
余白は機能のまとまりを示すために使う。
装飾のためのカードや影は使わない。
背景は白または Radix gray の薄い面、境界線は gray 系の細い線を基本にする。
Run や選択中タブなど、行動の焦点だけに blue を使う。

## Completion Conditions

- デスクトップ幅で、上部ツールバーと左右 2 ペインのコードエディタ/結果ペインが表示される。
- 上部ツールバーに、言語切替、コンパイルオプション入力、`Run`、`Open`、`Save`、`Share` だけが主要操作として表示される。
- コードエディタは主作業領域として十分な面積を持ち、結果ペインと同時に読める。
- 結果ペインには `Output / Build / Assembly` タブがあり、Run 後は `Output` が自動選択される。
- `Output` で stdout、stderr、終了コード、実行状態を読める。
- `Build` でコンパイルログを読める。
- C 入力時は `Assembly` で readonly な生成アセンブリを読める。
- アセンブリ入力時は `Assembly` が誤解を生まない空状態または無効状態になる。
- Run 中は `Run` ボタンが実行中表示になって無効化され、前回結果ではなく現在の Run の状態が表示される。
- 成功、コンパイルエラー、実行時エラー、タイムアウト、実行中、Run 自体を完了できなかったエラーが短い status badge で区別され、詳細はログとして読める。
- `Open` と `Save` は必要時だけ小さなダイアログを開き、常設のファイルツリーやサイドバーを作らない。
- `Share` で現在のコード、言語、コンパイルオプションを含む共有 URL を作る操作が明確に見える。
- 初期ロード時にツールバーと画面骨格が先に表示され、エディタのロードで大きなレイアウトシフトやちらつきが起きない。
- ライトモード固定の UI として、白、黒、Radix gray、Radix blue を中心に統一されている。
- エラーなど意味のある状態以外で色を増やさず、グラデーションや装飾的なカードに頼らない。
- 狭い画面では `Code / Result` の切替でコードと結果を行き来できる。
- モバイル幅でも、共有 URL から復元されたコードと結果を読め、Run 操作が破綻しない。
- Radix Themes/Colors のコンポーネントと色トークンを土台にしつつ、Monaco Editor など用途に合う専用部品を適切に使っている。
